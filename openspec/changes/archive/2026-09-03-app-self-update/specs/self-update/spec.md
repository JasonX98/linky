## Purpose

使应用本体能够发现 GitHub 上新的正式发布版本，并在检测到更新时引导用户前往发布页自行下载更新。本能力只负责"检测与引导"，不涉及对应用自身文件的替换或覆盖。

## ADDED Requirements

### Requirement: 主动检查应用版本

系统 SHALL 允许用户从界面主动触发一次应用版本检查，查询 GitHub 上最新的正式发布版本。

#### Scenario: 用户触发检查

- **WHEN** 用户在"关于与更新"区域触发"检查更新"
- **THEN** 系统查询远端最新正式发布版本，并进入对应的检测结果状态

### Requirement: 发现新版本时展示并引导前往下载

系统 SHALL 在检测到远端正式发布版本高于当前版本时，展示包含远端版本号的"发现新版本"提示，并提供引导用户查看该版本发布页面的入口。

#### Scenario: 存在新版本

- **WHEN** 检测到远端版本新于当前应用版本
- **THEN** 系统展示包含远端版本号的"发现新版本"提示
- **AND** 系统提供"前往更新"入口

#### Scenario: 用户前往更新

- **WHEN** 用户激活"前往更新"入口
- **THEN** 系统使用系统默认浏览器打开该发布版本的 GitHub release 页面

### Requirement: 无新版本时提示已最新

系统 SHALL 在检测显示当前版本已为最新时，向用户提示"已是最新版本"。

#### Scenario: 检测到无新版本

- **WHEN** 远端最新发布版本不高于当前应用版本
- **THEN** 系统展示"已是最新版本"状态

### Requirement: 检测失败时友好降级

系统 SHALL 在版本检查因网络或远端不可用而无法完成时，向用户展示可理解的错误提示，且不中断应用其余功能的正常运行。

#### Scenario: 网络检测失败

- **WHEN** 查询远端最新版本失败（网络不可达、超时或远端返回错误）
- **THEN** 系统展示检测失败的提示
- **AND** 应用其他功能继续正常运行

### Requirement: 语义化版本比较规则

系统 SHALL 以语义化方式比较应用版本号，并正确处理发版 tag 的 `v` 前缀与构建号（`+build`）后缀。

#### Scenario: 带 v 前缀与构建后缀的比较

- **WHEN** 比较远端 `v1.0.4` 与当前 `1.0.3+0`
- **THEN** 系统判定远端为更高的版本

#### Scenario: 主次补丁相同视为无更新

- **WHEN** 远端 `v1.0.3` 与当前 `1.0.3+0` 的主次补丁号完全相同
- **THEN** 系统判定当前版本已为最新，无新版本
